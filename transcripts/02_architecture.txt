⏺ I compared ARCHITECTURE.md with the README and the deliverable spec. The
  direction is sound: SQLite, plain Python plus LiteLLM, terminal output. The
  big gap is that the spec asks mainly for how memory works, and the draft says
  very little about it. Below is what's missing, in priority order.

  1. Memory design is underspecified (the core ask)

  The spec wants to know what is kept, how changing facts are represented, and
  what gets forgotten or invalidated. Right now the draft has "sqlite +
  context.json + version logs".

  - Two stores is a problem. SQLite plus a free-form context.json means two
    sources of truth. I'd drop the JSON file and use one append-only facts
    table:
    fact_id, subject, attribute, value, unit, source_id (N09/INV-010-L01), 
    effective_from, recorded_at, status, supersedes_fact_id, author
  - Keep two dates per fact: when it takes effect (effective_from) and when it
    was recorded (recorded_at). That's what answers "what did we believe on
    Friday?" and covers rule 4 (future-dated facts).
  - Write the 4 conflict rules into the doc as a resolver that runs in code, not
    inside the LLM prompt.
  - Add an open_questions table (M99 recipe, INV-099) with a resolution link.
    Demo 3 depends on it.
  - "Forgotten" means status changes: superseded or retracted, and nothing is
    deleted. Say that outright, because it's a direct question in the spec.

  2. Separate code that computes from the LLM that talks

  This layer is missing entirely, and it's what makes "reproducible" and "never
  invents numbers" true:
  CSVs + notes → deterministic reconciliation/runway (pure Python) → facts + 
  findings (with IDs)
              → LLM: extract notes → candidate facts / rank + narrate findings
              → validator: every number & ID in output must exist in computed 
  results
  Turning the temperature down doesn't make results reproducible. Doing the
  numbers in code does.

  3. Some nodes contradict the README guardrails

  - Intervention Node "send message": the README says never contact vendors.
    Narrow it to drafting an action for a human to approve.
  - Function Node "forecast": the README says runway, not forecasting. Rename
    it.
  - Tool "modify": the README says GM edits are just new notes. Make it add_note
    only. Modifying or deleting would break the audit trail.
  - An agentic node fills context.json: an LLM writing memory with no checks is
    your riskiest component. Extracted facts need a cited source span and should
    land as asserted/unverified until checked.

  4. Missing sections

  - What you left out and why. The spec requires this. You can reuse the
    README's out-of-scope list.
  - How the brief is ranked. Give the formula, for example: deadline proximity
    (Tue noon cutoff) × dollar or stockout impact × whether it blocks other
    work.
  - Tools list. Something like get_reconciliation(item), get_runway(item),
    query_facts(subject, as_of), add_note(text), list_open_questions().

  5. Production failures are too generic

  "Integration, capability, eval scalability" are true of any system. The spec
  asks for likely failures of this one:
  - Note extraction gets a unit wrong (20 lb vs. 40 lb cases), so runway is
    silently wrong.
  - The LLM states a number nobody computed, or cites an ID that doesn't exist.
  - The count is wrong. Garbage in still reconciles neatly (closing chicken
    count).
  - Conflicting notes with the same timestamp or an ambiguous author.
  - Stale reference data with no note to override it, so nothing flags it.
  - Too many alerts. Maya ignores the brief if items 6–15 are noise.
  - Timezone or effective-date off-by-one errors (Sep 28 price, noon cutoff).

  6. Testing section is missing (about half a page)

  - Golden tests on the data packet: INV-010 shows about $378 over, chicken
    shows about 48 lb, rice/beans/oil/avocado/eggs reconcile exactly.
  - The 4 demo scenarios as eval cases with expected facts and statuses.
  - Citation coverage: every number in the brief traces to a row or note ID
    (automated check).
  - As-of replay: rebuild memory as of Oct 1 and check the beliefs.
  - Adversarial notes: an ambiguous unit, a retraction of a retraction.
  - Usefulness: did Maya act on the top 3 items, the false-alarm rate, and
    whether Theo can read his section in under a minute.

  Small fixes

  - Delete the first bullet. It's the assignment prompt pasted in.
  - Remove the stray --> markers or replace them with one layer diagram.
  - Trigger Node: a daily 6 a.m. brief run is enough. Event triggers can be
    "future work".
